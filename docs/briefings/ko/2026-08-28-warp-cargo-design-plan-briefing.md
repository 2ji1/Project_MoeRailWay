## 이번 슬라이스의 목표

한 대의 열차와 한 줄의 선로라는 현재 프로토타입 위에 다음 판단을 추가합니다.

- 예고된 워프 출발·도착 지점을 보고 선로를 어디로 이어갈지 판단합니다.
- 제한된 화물칸 때문에 어떤 화물을 먼저 싣고 배송할지가 이동 경로에 따라 달라집니다.
- 워프 지점의 유한 수명 안에 배송하지 못하면 보상 기회를 잃습니다.

아직 계약, 현금 정산, 위험 투자, 대출은 추가하지 않습니다. 배송 시에는 이후 경제 시스템이 소비할 수 있는 `기본 배송 보상 누계`만 즉시 증가시킵니다.

## 확정한 핵심 규칙

1. 출발지와 도착지는 격자 안의 모든 셀에서 각각 독립적으로 뽑습니다.
2. 현재 선로, 열차 위치, 도달 가능성은 추첨에 관여하지 않습니다.
3. 출발지와 도착지가 같은 셀로 뽑혀도 다시 뽑지 않습니다.
4. 열차 뒤쪽이나 잠긴 선로 때문에 도달 불가능해도 그대로 유지합니다.
5. 예고 상태는 정보만 보여주며 선로 형상을 바꾸는 접촉 앵커를 아직 만들지 않습니다.
6. 활성화될 때 기존 `RouteContactAnchor`에 정확한 두 셀을 전달합니다.
7. 화물은 자동으로 가장 낮은 번호의 빈 슬롯에 적재됩니다.
8. 가득 찬 상태에서는 적재되지 않으며 출발지는 만료 전까지 활성 상태로 남습니다.
9. 동일 화물의 도착지를 통과하면 자동 배송되고 기본 보상이 정확히 한 번 지급됩니다.
10. 같은 틱에 접촉과 만료가 겹치면 열차 이동과 접촉을 먼저 처리합니다.
11. 정규 세션 종료 시 남은 예고, 활성 지점, 운송 중 화물은 벌점 없이 무효화합니다.

## 틱 처리 순서

한 틱에서는 다음 순서를 고정합니다.

1. 기존 예고의 카운트다운과 활성화를 처리합니다.
2. 우클릭 취소와 좌클릭 선로 입력을 처리합니다.
3. 선로 건설과 출차 조건을 처리합니다.
4. 열차를 기존 완성 선로 위에서 이동시킵니다.
5. 실제 이동 구간에서 출발·도착 지점 접촉을 순서대로 처리합니다.
6. 뒤쪽 선로를 회수합니다.
7. 워프 지점 수명을 감소시키고 만료를 처리합니다.
8. 세션 시간을 감소시키고 정규 종료를 처리합니다.
9. 읽기 전용 스냅샷과 결과를 한 번만 발행합니다.

따라서 마지막 수명 틱에 도착한 화물은 먼저 배송되며, 같은 틱에 세션도 끝나더라도 배송 수와 보상은 최종 결과에 남습니다.

## Inspector 조정값

책임을 두 Resource로 나눕니다.

`WarpLifecycleBalance`

- 예고 시간: 기본 8초, 0~60초
- 생성 간격: 기본 12초, 0.1~120초
- 활성 수명: 기본 24~36초, 각 1~180초
- 동시 생존 쌍: 기본 3개, 1~6개

`CargoBalance`

- 기본 화물 슬롯: 2개, 1~8개
- 기본 배송 보상: 100, 0~1,000,000

실행 중에는 Resource를 직접 읽지 않고 세션 시작 시 값을 복사합니다. 잘못된 값은 자동 보정하지 않고 전체 필드 이름과 함께 시작 오류로 처리합니다.

## 화면 피드백

- 예고: 낮은 투명도의 채운 출발 형태와 테두리 도착 형태, 활성화 카운트다운
- 활성 출발지: 불투명하게 채운 형태
- 활성 도착지: 같은 색·형태의 테두리
- 운송 중: 출발지는 테두리로 바뀌고 화물 슬롯에는 채운 형태가 표시됨
- 배송: 슬롯이 비고 배송 수와 기본 보상이 즉시 증가
- 만료: 지점이 사라지고 해당 운송 화물 슬롯이 비워짐
- 정규 종료: 남은 지점과 화물 슬롯을 모두 비우되 벌점 문구는 표시하지 않음

색상만으로 구분하지 않고 원, 마름모, 사각형 형태를 함께 사용합니다. 텍스처, 최종 아이콘, 커스텀 폰트, 애니메이션, 오디오는 이번 범위에서 만들지 않습니다.

## 구현 작업 분할

1. 밸런스 Resource와 시드 기반 워프 수명주기
2. 구체적인 화물 슬롯과 기본 보상
3. 기존 선로 접촉 계약의 이동 구간 hit 조회 확장
4. 세션 틱 순서와 스냅샷·결과 통합
5. placeholder 화면 피드백과 Windows 종단 검증

모든 작업은 `RED → 최소 GREEN → 회귀 테스트 → 파일 허용목록 확인 → 정확 경로 stage → 집중 commit → 독립 사양 검토 → 독립 품질 검토` 순서를 고정합니다.

## 현재 미해결 질문

이번 슬라이스를 막는 미해결 설계 질문은 없습니다. 기본 배송 보상을 이후 현금·계약 시스템이 어떻게 소비할지, 슬롯 구매 비용을 어떻게 정할지, 최종 아트를 어떻게 제작할지, 어떤 클래스를 본 개발에서 추상화할지는 각각 후속 범위로 남겼습니다.
