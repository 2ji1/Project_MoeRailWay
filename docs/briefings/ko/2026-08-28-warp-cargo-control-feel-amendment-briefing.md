# Warp Cargo 조작감 보정 설계·계획 브리핑

- 날짜: 2026-08-28
- 상태: 사용자 검토용 초안
- 영어 정본 설계: `docs/superpowers/specs/2026-08-28-warp-cargo-control-feel-amendment-design.md`
- 영어 정본 구현 계획: `docs/superpowers/plans/2026-08-28-warp-cargo-control-feel-amendment.md`

이 문서는 검토를 돕는 한국어 요약이며 구현 기준은 위 영어 정본 두 문서입니다.

## 핵심 결론

이번 보정은 세 가지입니다.

1. 활성 Warp 칸의 정확한 중심을 선로 곡선의 스냅점으로 사용합니다.
2. 기차가 출차하면 출발 기점 마커가 0.75초 동안 디졸브되어 사라집니다.
3. 운행 중 유효한 끝점 좌클릭 드래그가 활성화되어 있으면 게임 도메인 시간은 기본 25%로 흐릅니다.

자동 경로 생성이나 Warp 보정은 추가하지 않습니다. 플레이어가 Warp 칸을 실제 선로 셀 순서에 포함해야 하며, 이미 잠긴 선로가 Warp 중심을 지나지 않으면 그 Warp는 그대로 불가능할 수 있습니다.

## Warp 중심 스냅

기존 구현은 선로 중심선이 Warp 칸 안으로 들어오기만 하면 접촉으로 인정했습니다. 그래서 화면상 선로가 Warp 마커 중심을 비껴가도 적재나 배송이 먼저 일어날 수 있었습니다.

보정 후에는 다음과 같이 동작합니다.

- 예고 상태는 지금처럼 선로에 아무 영향도 주지 않습니다.
- 활성화된 출발·도착 Warp는 칸 중심에 정확한 스냅점을 만듭니다.
- 플레이어가 그 Warp 칸을 선로 셀 순서에 포함했을 때만 스냅 제약이 적용됩니다.
- 직선은 칸 중심을 그대로 통과합니다.
- `1x1`, `2x2`, `3x3` 곡선은 기존 셀 소유권·크기·진입/진출 방향을 유지하면서 Warp 중심을 정확히 지나는 곡선으로 만들어집니다.
- 여러 Warp가 같은 칸에 있으면 선로 스냅점은 하나지만 적재·배송 판정은 기존 ID 순서대로 각각 처리합니다.
- 잠긴 선로는 절대 바꾸지 않습니다. 중심을 지나지 않으면 `접촉 불가` 상태가 됩니다.
- 적재와 배송도 칸 경계가 아니라 실제 Warp 중심을 열차가 지날 때 발생합니다.

따라서 Warp가 선로 모양을 유도하지만, Warp가 선로 셀을 대신 골라 주거나 자동으로 선로를 끌어오지는 않습니다.

## 계획 중 25% 감속

Godot 전체의 `Engine.time_scale`은 사용하지 않습니다. 이를 사용하면 마우스 입력과 화면 갱신까지 느려져 조작감이 둔해질 수 있기 때문입니다.

대신 물리 프레임마다 마우스 입력과 고스트 선로 후보는 계속 처리하고, 다음 항목만 기본 네 프레임에 한 번 전진시킵니다.

- 열차 진행
- 선로 건설 진행
- 후방 선로 회수
- Warp 예고, 활성화, 수명, 생성 주기
- 세션 제한 시간
- 적재·배송 접촉 판정

유효한 끝점 드래그가 실제로 시작된 다음 프레임부터 감속됩니다. 잘못된 칸을 누르거나, 거절된 상태에서 버튼만 계속 누르고 있거나, 마우스를 올려 두기만 한 경우에는 감속되지 않습니다. 출차 전은 원래 제한 시간이 흐르지 않으므로 정상 속도를 유지합니다.

버튼을 놓거나 우클릭으로 취소하면 남은 감속 누적값은 버립니다. 해제 순간에 열차·건설·회수·Warp 시간이 몰아서 진행되는 보상성 점프는 없습니다.

현재 구현은 활성 드래그 동안 회수를 완전히 막고 있습니다. 이번 계획에서는 회수를 단순 정지시키지 않고, 드래그 원본과 현재 후보 양쪽에 같은 회수 결과를 적용합니다. 그래서 우클릭으로 편집을 취소해도 드래그 중 실제로 흐른 건설·회수 시간까지 과거로 되돌아가지는 않습니다.

같은 원칙을 Warp 앵커에도 적용합니다. 드래그 중 Warp가 활성화되거나 적재·배송·만료로 앵커가 사라지면 최신 앵커 집합을 드래그 원본과 현재 후보 양쪽에 반영합니다. 이후 우클릭 취소나 좌클릭 확정은 플레이어의 선로 편집만 되돌리거나 확정하며, 실제로 흐른 Warp 수명주기를 과거 상태로 되감지 않습니다.

화면에는 감속 중 `PLANNING 25%`를 표시합니다. 마우스, 고스트 선로, 호버, 기점 디졸브는 계속 실시간으로 움직입니다.

## 기점 디졸브

- 출차 전에는 지금처럼 기점 마커가 완전히 보입니다.
- 첫 운행 상태가 화면에 표시되는 순간 0.75초 디졸브를 시작합니다.
- 이후 운행 스냅샷이 들어와도 애니메이션을 다시 시작하지 않습니다.
- 새 세션을 구성할 때만 초기화합니다.
- 기점 셀, 선로 거리 원점, 열차 위치 계산은 그대로이며 그림만 사라집니다.

## 구현 순서

계획은 다섯 개의 집중 구현 태스크와 마지막 무변경 증거 게이트로 나눴습니다.

1. Warp 정확 중심 스냅과 중심 접촉 판정
2. 유효한 계획 제스처 중 도메인 25% 감속 및 제스처 중 회수
3. `PLANNING 25%` 표시와 기점 디졸브
4. 후방 회수가 기점을 지나간 뒤 해당 기점 좌표 재사용
5. 기차가 현재 끝점까지 선형을 잠근 상황에서도, 다음 Warp 스냅 칸에서 시작되는 첫 곡선을 끊김 없이 연결

각 태스크는 반드시 RED 테스트, 최소 GREEN 구현, 회귀 테스트, 명시적 파일 allowlist, 정확 경로 스테이징, 집중 커밋, 독립 사양 검토, 독립 품질 검토 순서로 진행합니다.

Task 5까지 끝나면 파일을 더 고치지 않고 전체 자동 게이트와 Windows 수동 검증을 실행합니다. 실패가 나오면 새 테스트-only 태스크를 만들지 않고 원인을 소유한 Task 1, 2, 3, 4, 5의 검토 수정으로 돌아갑니다.

수동 검증에서 확인된 추가 계약은 다음과 같습니다. 출차 좌표는 열차 뒤 회수가 아직 기점을 지나지 않은 동안에는 계속 예약할 수 없습니다. 회수가 기점을 지나 활성 선로의 직전 좌표가 다른 칸으로 전진한 뒤에는, 사라진 출차 좌표를 일반 선로 칸처럼 다시 예약할 수 있습니다. 이때 선로 한 칸을 정상 소비하고 새 경로 번호와 절대 거리를 받으며, 거리 원점이나 디졸브된 기점 표시를 되살리지는 않습니다. 같은 좌표에 Warp가 있으면 새 활성 선로 기록의 중심 거리를 우선하고, 활성 기록이 없는 원래 기점 상태에서만 거리 `0.0`을 사용합니다. 부분 회수된 고정 선형은 전체 footprint와 열차 샘플링용 중심선을 그대로 보존하고, 새 선로 충돌 검사에 쓰는 복제본에서 회수 맵에 기록된 정확한 셀만 제외합니다.

이번 수동 재현에서 추가로 확인된 문제는 기차가 기존 끝점까지 선형을 잠근 뒤 발생했습니다. Warp 칸 한 칸은 직선으로 설치됐지만, 같은 드래그의 다음 칸이 첫 곡선을 만들 때 곡선의 미세 샘플 방향을 경계 진입 방향으로 잘못 판단해 뒤쪽 suffix가 거절됐습니다. 보정은 곡선이 이미 가진 공식 진입 방향을 연결 검사에 사용합니다. 잠긴 선형은 바꾸지 않고 새 곡선의 시작점만 기존 끝점에 잇고, Warp 중심점과 나머지 곡선은 그대로 유지합니다. 옆이나 뒤로 끊기는 잘못된 연결은 계속 거절합니다.

자동 테스트 목표는 기존 23개 스위트에 새 표현 스위트 하나를 추가한 정확히 24개입니다. 기존 네 통합 러너와 Warp Cargo 통합 러너도 모두 통과해야 합니다.

## 수동 검증에서 볼 항목

최종 구현 HEAD에서 `960x540`, `1280x720`, `1600x900`, `1920x1080` 네 크기를 확인합니다.

- 직선 선로가 Warp 중심을 정확히 지나는지
- 곡선 선로가 Warp 중심을 스냅점으로 삼아 자연스럽게 형성되는지
- 이미 잠긴 선로를 Warp가 억지로 움직이지 않는지
- 열차가 마커 중심을 지날 때 적재·배송되는지
- 좌클릭 드래그 동안 고스트 선로는 즉시 반응하는지
- 같은 동안 열차·건설·회수·Warp·제한 시간이 함께 약 25%로 느려지는지
- 드래그를 놓거나 취소했을 때 밀린 진행이 한꺼번에 튀지 않는지
- `PLANNING 25%`가 올바른 동안에만 보이는지
- `PLANNING 25%`가 네 해상도에서 다른 HUD나 선로를 가리지 않고 읽기 쉬운지
- 출차 뒤 기점 마커가 부드럽게 사라지는지
- 후방 회수가 기점을 지난 뒤 사라진 기점 좌표를 새 선로로 다시 사용할 수 있는지
- Warp 및 새 표시가 마우스 입력을 가로채지 않는지

## 범위 밖

정지, 일시정지, 자동 길찾기, 선로 자동 생성, Warp 재추첨·이동·도달 가능성 보정, 위험·투자, 계약 경제, 신용 생존, 커스텀 아트, 오디오, 모바일은 이번 작업에 포함하지 않습니다.
