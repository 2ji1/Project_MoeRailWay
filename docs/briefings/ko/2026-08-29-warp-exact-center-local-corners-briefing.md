## 결론

실패한 B 방식은 큰 곡선을 작은 곡선으로 내렸지만, 중심선 전체를 하나의 cubic으로 만드는 원인은 그대로여서 작은 S자 굴곡이 남았습니다. 새 방식은 Warp 존재 여부와 무관하게 모든 unlocked `1x1`, `2x2`, `3x3` 곡선에 적용하며, 소유권을 시각 문제 때문에 축소하지 않습니다.

정확 중심을 지나는 선형은 다음처럼 만듭니다.

1. 진입 경계, Warp 정확 중심, 진출 경계를 순서대로 잇는 직선 골격을 만듭니다.
2. 진입·진출 방향을 유지하는 짧은 지지점을 둡니다.
3. 실제로 방향이 바뀌는 지점 주변 최대 반 셀에만 곡률을 넣습니다.
4. Warp 중심이 꺾임점이면 그 점을 잘라 내지 않고, 중심을 정확히 통과하는 작은 국소 곡선 두 개로 잇습니다.
5. 곡률 구간 밖의 샘플은 직선 골격과 정확히 같게 유지합니다.

Warp가 없는 일반 곡선도 진입·진출 지지점 사이를 직선 골격으로 잇고 두 끝의 실제 방향 전환부만 둥글립니다. 정확 중심을 통과하면서 그 지점에서 방향까지 바꾸려면 일반적인 코너 잘라내기만으로는 해결할 수 없습니다. 이때만 공통 골격에 정확 중심 hard knot와 작은 국소 cubic을 추가합니다.

## 함께 정리하는 소비 로직

현재 Resolver와 Runtime이 exact-center를 서로 다르게 검사합니다. Resolver는 저장된 점만 보고, Runtime은 선분에 투영합니다. 이를 `TrackGeometryPiece`의 하나의 투영 함수로 통합합니다.

일반 `CELL_ENTRY`는 두 의미를 유지합니다.

- 후보 곡선 판정: 중심선이 실제 셀 공간을 통과하는지 확인
- 게임플레이 접촉: 명목거리 1/8마다 바깥에서 안으로 들어오는지 확인

두 로직은 같은 것이 아니므로 합치지 않습니다. 다만 Runtime 안에 별도로 적힌 `8.0`은 기존 접촉 상수를 사용하게 하고, 활성 구간 셀 접촉 계산은 `TrackGeometryPiece`에 위임합니다.

중심선 저장 16분할, 게임플레이 접촉 8분할, 렌더의 양 끝 포함 9점도 서로 다른 계약이므로 하나의 전역 설정으로 합치지 않습니다.

## 보존되는 항목

- 선로 셀 순서와 재고
- `1x1`, `2x2`, `3x3` 소유 범위와 footprint
- 정확 중심의 명목거리 `record offset + 0.5`
- 잠긴 선형의 바이트 단위 불변성
- 직선 선형의 byte 단위 불변성
- 이미 잠긴 곡선 선형의 byte 단위 불변성
- 열차 시간, 건설, 회수, Warp RNG, 적재·배송, 보상
- 결정론과 nonzero grid origin

`TrackSystem`, `TrainSystem`, `SessionController`, `WarpPairSystem`, `CargoSystem`, 실제 렌더 코드에는 생산 변경을 넣지 않습니다. Resolver가 모든 unlocked 곡선에 공통 중심선을 공급하고 렌더는 기존 `sample_nominal()` 소비를 유지합니다.

## 검증

자동 테스트는 Warp 없는 경우와 exact-center가 있는 경우 모두에서 여덟 방향의 `1x1`, `2x2`, `3x3`, 직선 골격, 국소 곡률, footprint, 소유권, 고정 선형, 회수, 명목 샘플, 렌더 1/8 샘플과 결정론을 확인합니다.

수동 테스트는 사용자가 수행합니다. `960x540`, `1280x720`, `1600x900`, `1920x1080`에서 긴 S자가 사라지고 실제 꺾임 주변만 둥글며 Warp 중심을 정확히 지나는지 확인하기 전까지 결과는 `PENDING`입니다.

Risk & Investment, 자동 경로 보정, Warp 재추첨, 곡률 Resource, arc-length 속도 보정, snapshot 성능 리팩터링은 포함하지 않습니다.

## 수동 테스트에서 발견된 인접 회전 보정

`1280x720` 수동 테스트에서 `(10, 7)` 끝점의 좌우 예약이 모두 멈추는 현상이 확인되었습니다. 동일한 끝부분을 재현한 결과, Warp exact 앵커를 제거해도 좌우는 `final_overlap`으로 거절되고 아래 직진은 승인되었습니다.

기존 Resolver는 겹친 두 곡선을 항상 함께 축소합니다. `3x3 + 2x2`를 `2x2 + 1x1`로 줄인 뒤에도 겹치면, 한쪽이 이미 1x1이라는 이유로 즉시 실패하여 가능한 `1x1 + 1x1` 조합을 검사하지 않습니다.

승인된 보정은 겹친 후보 중 아직 축소 가능한 후보만 한 단계 더 줄입니다. 두 후보가 모두 1x1인데도 실제 footprint가 겹칠 때만 기존처럼 거절합니다. locked geometry, exact-center, route 순서, 재고, 실제 footprint 충돌은 완화하지 않습니다. 해당 좌우 드래그와 오른쪽 Warp 정확 중심 통과는 사용자가 다시 수동 확인하며 상태는 그때까지 `PENDING`입니다.

GREEN 확인 중 같은 이유로 거절되던 기존 밀집 회전 테스트 두 개도 최종 footprint가 모두 분리되는 합법 경로로 확인되었습니다. 이 테스트들은 승인 회귀로 바꾸되, serial 단일 소유, locked ledger 불변, 재고 보존, 건설과 열차 샘플링까지 검증합니다. 실제 1x1 footprint가 중복되는 음성 테스트는 계속 `final_overlap`을 요구하므로 충돌 규칙 자체는 완화되지 않습니다.

## Warp 비의존 일반화 정정

사용자는 곡률 개선을 Warp exact-center 전용이 아니라 모든 일반 곡선에도 적용할 의도였음을 재확인했습니다. 따라서 “앵커 없는 곡선은 기존 byte를 유지한다”는 이전 제한은 폐기합니다. exact-center는 공통 생성기를 켜는 조건이 아니라, 같은 직선 골격에 정확 중심 통과점을 추가하는 제약입니다.

자동 테스트와 독립 검토가 통과하면 feature를 원격에 게시하고 `main` 대상 PR을 merge commit으로 병합한 뒤, 보호된 로컬 `main`을 fast-forward하고 같은 전체 게이트를 다시 실행합니다. 수동 시각 판정은 사용자가 직접 확인하기 전까지 계속 `PENDING`입니다.
