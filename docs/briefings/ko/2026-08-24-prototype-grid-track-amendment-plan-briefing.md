- 완료 태그 예정: `prototype-m4`

## 핵심 구현 결과

다음 세션은 기존 연속 폴리라인의 일부 기능을 덧붙이는 작업이 아니라 선로 도메인의 소유 단위를 교체합니다.

- 플레이어의 실제 드래그가 통과한 상하좌우 격자 칸을 순서대로 기록합니다.
- 시스템은 목적지 경로를 대신 찾거나 대각선 지름길을 만들지 않습니다.
- COMPACT·STANDARD·EXPANSIVE 격자의 중앙 정렬 원점을 세션 시작 설정에 한 번 복사하고, 입력 판정·출발점 스냅·커브 중심선·화면 표시·기차 위치가 모두 같은 원점을 사용합니다.
- 새로 예약된 고유 칸 한 개가 재고 한 칸을 정확히 한 번 소비합니다.
- 같은 예약 칸이 직선에서 커브로 다시 분류되어도 추가 재고를 소비하지 않습니다.
- `1×1`, `2×2`, `3×3` 커브는 각각 노선 칸 `1`, `3`, `5`개와 명목거리 `1`, `3`, `5`를 가집니다.
- 가까운 미확정 커브끼리 겹치면 양쪽을 한 단계씩 축소하여 다시 계산합니다.
- 예약 선로는 반투명 고스트이며 아직 미확정인 뒤쪽 선형은 입력에 따라 다시 배치될 수 있습니다.
- 어떤 커브의 첫 칸이 건설을 시작하면 커브 전체 선형이 잠깁니다.
- 한 칸은 `예약 고스트 → 건설 중 → 완성` 순서로 변하고, 100% 완성 전에는 기차가 진입할 수 없습니다.
- 기차는 완성된 중심선을 연속적으로 이동하지만 속도와 도착시간은 초당 명목 칸 수를 기준으로 계산합니다.
- `3×3` 커브 통과시간은 직선 다섯 칸과 같습니다.
- 후방 회수는 복합 커브도 한 칸씩 순서대로 환급합니다.

## 워프 칸과의 경계

이번 슬라이스는 워프 화물 자체를 만들지 않습니다. 대신 이후 워프 시스템이 무작위로 정한 칸을 그대로 넘겨줄 수 있는 `RouteContactAnchor` 경계를 완성합니다.

- 선형 계산은 워프 칸의 사각 점유영역만 덮는 것으로 끝내지 않고 실제 중심선이 그 칸에 접하는지 검사합니다.
- 워프 칸 때문에 큰 커브가 해당 칸을 비껴가면 더 작은 커브나 직선을 선택합니다.
- 넘겨받은 워프 칸을 이동, 재추첨, 도달 가능성 검사 또는 노선 기준으로 보정하지 않습니다.
- 실제 무작위 쌍 생성, 수명, 예고, 적재, 배송, 만료는 순연된 `proto/04-warp-cargo`가 담당합니다.
- 워프 화물 슬라이스는 격자 노선이나 커브 계산을 다시 구현하지 않고 이번 접점 계약만 사용합니다.

## 초기 조정값

기존 `prototype-m3`의 시간 비율을 최대한 유지하도록 한 칸을 논리 좌표 `40`으로 환산했습니다.

| 항목 | 초기값 |
|---|---:|
| 표준 격자 | `30 × 14` |
| 중앙 정렬 원점 | COMPACT `(10, 10)` / STANDARD `(0, 0)` / EXPANSIVE `(30, 30)` |
| 총 선로 재고 | `18칸` |
| 후방 회수 간격 | `6칸` |
| 건설 속도 | `초당 3칸` |
| 열차 속도 | `초당 1.5칸` |
| 출발에 필요한 완성 선로 | `9칸` |
| 선로 끝 긴급 경고 | `3초` |

이 숫자는 최초 격자 프로토타입의 조정값입니다. 정수 칸 소유와 명목거리의 의미는 고정 규칙이지만 수치는 플레이테스트 후 Inspector에서 조정할 수 있습니다.

## 개발 작업 분할

1. 격자 설정과 화면 좌표 변환
2. 정수 칸 재고와 순서가 있는 셀 노선
3. 직선·커브·겹침 축소·워프 접점 선형 계산
4. 기존 앱을 건드리지 않는 격자 건설·회수 런타임
5. 기존 열차를 건드리지 않는 명목 칸 이동 모듈
6. 기존 화면을 건드리지 않는 마우스 통과 칸 계산기
7. 공개 시스템·고정 틱 제어·화면·테스트의 원자적 격자 전환
8. 구형 계약 삭제, 전체 자동 테스트, Windows 수동 검증, 독립 검토

각 작업은 다음 작업이 의존할 수 있는 명시적 인터페이스와 테스트를 남깁니다. 새 경로가 계획의 파일 허용목록을 벗어나면 구현을 중단하고 계획 수정 승인을 먼저 받습니다.

특히 프리셋별 통합 테스트에서 마우스로 판정한 칸 중심, 계산된 선로 중심선, 렌더링 좌표, 기차 위치가 같은 논리 좌표인지 검증하도록 계획했습니다. 중앙 여백이 있는 COMPACT와 EXPANSIVE도 반드시 포함합니다.

## 삭제·대체 로그

영어 실행 계획의 `Supersession and Deletion Ledger`에 아래 내용을 정식 기록했습니다.

### 실행 기준에서 삭제한 항목

- 연속 `PackedVector2Array`를 선로 소유권으로 삼는 규칙
- 픽셀·논리 좌표 실수 길이만큼 재고를 소비하는 규칙
- 자유형 표본점, 대각선 선분, 표본 최소거리, 교차 여유거리, 임의 선분 투영 취소
- 선분 일부만 건설하거나 일부만 잘라 회수하는 규칙
- 원시 마우스 선을 그대로 선로 그림으로 사용하는 규칙
- 격자 선로 정본에서 미래 유료 철거와 교차의 상세 형상을 미리 소유하던 규칙
- 워프 화물 단계가 선형 선택이나 도달 가능성 보정을 다시 구현할 수 있는 중복 책임
- 전체 게임플레이 정본의 자유형 길이 선로 절을 격자 규칙 요약으로 교체하고 연속 위치 기준 유료 철거 문장을 삭제했습니다.

### 유지한 이력

- `prototype-m3` 태그와 기존 영어 설계·실행 계획은 완료 증거로 삭제하지 않았습니다.
- 기존 계획 상단에 “완료된 역사 문서이며 재개 대상이 아님”을 표시했습니다.
- 출발 후보 RNG, 고정 틱 순서, 화면 크기 변환, 분리된 스냅샷, 결과 한 번 처리, 에디터 격리 검증 절차는 재사용합니다.

### 실제로 삭제한 후속 계획 범위

- 감사한 저장소에는 `proto/03` 이후의 상세 실행 계획 파일이 아직 없었습니다. 따라서 존재하지 않는 문서 파일을 삭제하지 않았습니다.
- 대신 살아 있는 개발 전략에서 `proto/03-grid-track-amendment`를 새로 삽입했습니다.
- 기존 Warp Cargo부터 Playtest Ready까지를 `proto/04`부터 `proto/08`로 순연했습니다.
- Warp Cargo와 Risk Investment가 격자 선로·커브·기본 건설·기차 이동을 중복 소유하지 못하도록 범위를 삭제하고 “이번 계약을 소비한다”로 바꿨습니다.
- 태그 범위를 `prototype-m1`~`prototype-m9`로 갱신했습니다.
